# REQ-012 实体级 GEO 与结构化竞品

- 状态：demo 待确认（2026-10-09 三口径已定稿）
- 来源：用户实战需求——"我的品牌是苹果，但我想优化的是具体某一个产品（如 iPhone 17 Pro）"。当前系统只有 brand 一个颗粒度，产品信息只能混进词表/知识库，报表只出品牌整体分
- 参考：腾讯 AnswerBit（answerbit.qq.com）OpenAPI 的品牌模型（品牌含别名/官网/描述；竞品为完整对象）。注意：AnswerBit 本身无产品实体层，实体化是我们超越其模型的自行设计

## 已定稿三口径（2026-10-09 用户选择）

1. **实体完全独立（方案 A）**：每个实体有独立词表、知识库、独立题库（每实体 25 题）、独立采样诊断、独立 GEO 分。成本随实体数线性增长，用户知悉并接受
2. **实体分数放二级页**：数据大盘主视图保持品牌级，实体分数/趋势作为二级明细页（从大盘点击进入）
3. **竞品结构化**：新增 competitor 对象（名称/别名/官网/描述），挂品牌下，诊断报告作为对照组呈现

## 数据模型变更

```
entity 表：id, brand_id(FK), name, alias, website, description, status('启用','停用'), created_at
competitor 表：id, brand_id(FK), name, alias, website, description, created_at
既有表下沉：brand_word / brand_knowledge / question / sample / judgement / advice / strategy / brief / article
  → 全部加 entity_id 列（NOT NULL，默认 0 = 品牌整体遗留数据）
迁移规则：存量品牌自动创建一个同名"默认实体"承接既有数据（user 无感知）
```

## 业务流程变化

- 品牌锁定后先建实体（≥1 个）；词表/知识库/题库/采样/诊断入口全部移到实体卡片上
- 品牌级保留：品牌解析、品牌锁定、竞品管理
- 诊断按实体跑：一次实体诊断 = 该实体题库 25 题全平台采样+判定，成本与现状一个品牌相同
- 大盘主视图：品牌整体分 = 各实体最新分的加权（或独立跑一轮品牌级题库，开发时定，倾向前者省成本）
